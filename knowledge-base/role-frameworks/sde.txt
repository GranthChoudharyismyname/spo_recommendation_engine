1. WHAT AN SDE RESUME IS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
An SDE resume must demonstrate strong algorithmic problem-solving ability, computer science fundamentals, scalable systems design, and clean engineering craftsmanship.
Recruiters evaluate candidates across three primary capabilities:
1. Algorithmic Mastery & Speed: Competitive programming ratings, clean complexity analysis, and problem-solving under pressure.
2. Core Computer Science Fundamentals: Operating systems, concurrency, memory management, networks, database optimization, and object-oriented design.
3. Software Engineering & Systems Craftsmanship: Scalable backend architectures, distributed systems, REST/gRPC APIs, microservices, open-source contributions, and production deployment.
The fundamental rule: Show measurable engineering impact — latency reduction, QPS (queries per second) scaling, throughput gains, concurrency safety, and clean software architecture.

2. CORE EVALUATION BENCHMARKS — THE SEVEN PILLARS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
───── PILLAR 1: BRANCH / DEPARTMENT ELIGIBILITY ─────
Branch reflects formal coursework and exposure to core computer science, discrete math, and computing hardware:
• Very Good (Strong Computational & Algorithmic Signal):
  - Computer Science & Engineering (CSE)
  - Electrical Engineering (EE)
  - Mathematics & Scientific Computing (MTH)
  - Statistics & Data Science (SDS)
• No Signal / Neutral (Other Branches: ME, CHE, CE, MSE, BSBE, ECO):
  - Students from other branches are fully considered IF and ONLY IF they demonstrate strong individual proof of software engineering capability (high CP rating on Codeforces/LeetCode, ESO207/DSA course, strong backend/systems projects, GSoC, or GitHub repositories).
───── PILLAR 2: CPI (ACADEMIC PERFORMANCE) ─────
IITK uses a 10-point CPI scale. SDE recruiters use CPI as a strong indicator of discipline, problem-solving consistency, and academic capability:
• CPI ≥ 9.0: Very Very Good / Outstanding (Top-tier standing; clears all company shortlists and test cutoffs).
• CPI 8.5 – 9.0: Very Good (Comfortably above shortlisting criteria for all top tech MNCs).
• CPI 8.0 – 8.5: Good (Solid benchmark; meets criteria for Google, Microsoft, Amazon, Flipkart, Uber).
• CPI 7.5 – 8.0: Above Average (Passable for almost all SDE shortlists if backed by solid CP or development projects).
• CPI 7.0 – 7.5: Average (Standard baseline; requires good projects or CP ratings to stand out).
• CPI 6.5 – 7.0: Okay / Baseline Floor (Minimum threshold for general shortlisting; uphill battle without strong coding spikes).
• CPI < 6.5: Below Par / High Risk (Significant risk of being filtered out by strict GPA thresholds at resume drop).
───── PILLAR 3: WORK EXPERIENCE & RESEARCH PEDIGREE ─────
Evaluated across Industry Software Internships and Academic/Industrial Computer Science Research:
A. Industry & Corporate Work Experience:
• Outstanding:
  - Software Engineering internship at Tier-1 tech or product firms (Google, Microsoft, Amazon, Flipkart, Databricks, Rubrik, Uber, Atlassian, Sprinklr, Goldman Sachs).
  - High-impact backend, systems, or infrastructure internship at well-funded / listed tech unicorns.
• Very Good:
  - Software Engineering internship at established tech firms, Series A+ startups, or high-growth tech companies.
• Good:
  - General software development, QA/SDET, or full-stack engineering trainee experience.
• Not Important / Diluting:
  - Non-technical internships (marketing, operations, sales) or basic data entry roles.
B. Academic & Industrial Research Experience:
• Outstanding:
  - Software Systems, Compilers, Distributed Systems, or Security research internship at Top Global Universities (MIT, Stanford, CMU, Oxford, Berkeley, ETH Zurich, EPFL).
  - Global research fellowships: MITACS Globalink, DAAD WISE, CERN openlab.
  - Industrial research labs: Microsoft Research (MSR), Google Research, Adobe Research.
  - Published/accepted paper in top systems, algorithms, or software engineering conferences (OSDI, SOSP, SIGCOMM, PLDI, ICSE, POPL).
• Very Good:
  - SURGE at IITK in systems, algorithms, networking, or security under CSE/EE faculty.
  - Research at top Indian institutions: IISc Bangalore, TIFR, IITB/IITD/IITM.
• Good:
  - Formal BTP (Bachelor Thesis Project) or UGP at IITK in computer science or applied software engineering.
• Not Important / Diluting:
  - Informal/remote theoretical projects without verifiable code artifacts or faculty backing.
───── PILLAR 4: COMPETITIVE PROGRAMMING (CP) & PROBLEM-SOLVING SPIKES ─────
Competitive programming is the single highest-signal objective proof of algorithmic speed and precision for SDE roles:
• Codeforces (CF) Rating:
  - 2000+ (Master / Grandmaster): Above Excellent (Tier-1 SDE magnet; elite algorithmic signal).
  - 1900 – 1999 (Candidate Master): Excellent (Strong differentiator).
  - 1800 – 1899 (High Expert): Very Good (Solid standing).
  - 1700 – 1799 (Expert): Good (Respectable baseline).
  - 1600 – 1699 (Expert floor): Positive signal.
  - < 1600: Sub-par (Do NOT highlight on the resume).
• LeetCode Rating / Standings:
  - LeetCode Guardian / 2100+ Rating: Very Good / Excellent.
  - LeetCode Knight / 1850 – 2100 Rating: Good.
• Other High-Impact CP & Coding Spikes:
  - ICPC Regionalist / World Finalist: Outstanding (Top-tier shortlist booster across all tech firms).
  - Google Code Jam / Kickstart / Hash Code top global ranks (Top 100/500).
  - Meta Hacker Cup Round 2/3 qualifier.
  - Google Summer of Code (GSoC) Contributor / Mentor: Very Good (Proves real-world open-source software collaboration).
───── PILLAR 5: CORE COMPUTER SCIENCE COURSEWORK & FOUNDATIONS ─────
Recruiters look for strong formal foundations in core systems and algorithms:
Key Courses to Highlight:
- Data Structures & Algorithms (ESO207 / CS210)
- Operating Systems & System Programming (CS330)
- Computer Networks (CS425)
- Database Management Systems (CS634 / CS315)
- Principles of Programming Languages & Compilers (CS345 / CS335)
- Distributed Systems / Cloud Computing (CS654 / CS698)
- Computer Organization & Architecture (CS220 / EE380)
Feedback Rule: If a non-CSE student has completed ESO207 (Data Structures and Algorithms) or CS330 (Operating Systems), advise them to prominently display it in a "Relevant Coursework" section to demonstrate equivalence to CSE students.
───── PILLAR 6: TECHNICAL PROJECTS & SOFTWARE ARTIFACTS ─────
• Baseline Expectation: Having **at least ONE coding-based project (Data Science, Machine Learning, SDE, systems, or any code-driven technical project) is extremely important and heavily expected, however simple** (e.g. full-stack web application, ML model pipeline, backend API, mobile app, CLI tool, or algorithmic system). Resumes without any coding-based projects face a severe disadvantage during screening.
Project Quality Tiers (Good / Very Good):
Having scalable, systems-oriented, or production-grade projects elevates the candidate to Good or Very Good standing:
1. Scalable Backend & Distributed Systems (Very Good / Outstanding):
   - Microservices architecture, gRPC/REST APIs, asynchronous task queues (RabbitMQ, Kafka, Celery), caching layers (Redis), database sharding/indexing, rate limiting, and Docker/Kubernetes container orchestration.
2. Low-Level Systems, Concurrency & Networking (Very Good / Outstanding):
   - Multi-threaded TCP/HTTP server in C++/Rust, custom memory allocator, lock-free data structures, key-value storage engine (LSM tree/B-Tree), compiler/interpreter, or OS kernel modules.
3. Production Full-Stack Applications (Good / Very Good):
   - End-to-end full-stack app (React/Next.js + Node.js/Go/Python + PostgreSQL/MongoDB), OAuth/JWT authentication, CI/CD pipeline, and deployed to live production with real users.
4. Open-Source Contributions (Good / Very Good):
   - Merged pull requests in major open-source ecosystems, actively maintained GitHub repositories with stars/forks, or developer tooling.
───── PILLAR 7: POSITIONS OF RESPONSIBILITY (PoR) ─────
PoR Policy for SDE Roles:
• Positions of Responsibility are **"Good to Have"** but **NOT mandatory**.
• Not having a PoR carries **zero penalty** (SDE hiring focuses almost entirely on coding competence, projects, and fundamentals).
• Technical PoRs (e.g., Coordinator/Executive in Programming Club, Web Division Head, Hackathon Lead Organizer, FOSS Lead) are a valuable positive signal of technical leadership and team collaboration.

WHAT DILUTES AN SDE RESUME (RED FLAGS TO REMOVE)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Static UI / Tutorial Clones:
   - Superficial frontend clones without real functionality (e.g. static Netflix UI clone, Spotify landing page using only HTML/CSS). Advise replacing with functional backend, database, authentication, or API logic.
2. Missing GitHub / Live Links:
   - Listing complex projects without any verifiable GitHub link, live deployment URL, or code repository.
3. Unrelated Non-Technical Certificates:
   - Basic Coursera completion certificates or generic non-technical workshop certificates taking up valuable space.
